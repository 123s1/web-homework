# 博物馆预约系统——性能测试操作教程

> 本教程记录了在 VMware 虚拟机上从零搭建环境、运行性能测试1~4的完整步骤，任何人按照步骤操作即可复现全部测试结果。

---

## 一、环境准备

### 1.1 VMware 虚拟机部署要求

| 项目 | 要求 |
|---|---|
| 虚拟化平台 | VMware Workstation / VMware Fusion |
| 操作系统 | Ubuntu 22.04 LTS Server（**无桌面服务器版优先**） |
| 内存 | **8GB（固定，不使用动态内存）** |
| 磁盘 | ≥ 20GB 可用空间 |
| 虚拟机内安装 | JDK 21、MySQL 8.0 |
| 部署方式 | 项目打包后部署到虚拟机中运行 |

### 1.2 安装 JDK 21

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk

# 如果系统有多个 JDK，切换到 21
sudo update-alternatives --set java /usr/lib/jvm/java-21-openjdk-amd64/bin/java
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64

# 验证
java -version
# 应输出：openjdk version "21.x.x"
```

### 1.3 安装 Maven

```bash
sudo apt-get install -y maven

# 验证
mvn -version
```

### 1.4 安装 MySQL 8

```bash
sudo apt-get install -y mysql-server mysql-client

# 启动 MySQL
sudo systemctl start mysql
sudo systemctl enable mysql

# 验证
sudo mysql -e "SELECT VERSION();"
# 应输出 8.0.x
```

### 1.5 安装 ApacheBench（ab）

```bash
sudo apt-get install -y apache2-utils

# 验证
ab -V
```

### 1.6 安装 Node.js（前端需要，测试可选）

```bash
# 如果需要前端，安装 Node.js
sudo apt-get install -y nodejs npm
```

## 二、初始化数据库

### 2.1 创建数据库和用户

```bash
# 以 root 身份连接 MySQL 创建数据库和用户
sudo mysql -e "
CREATE DATABASE IF NOT EXISTS museum_reservation
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'museum'@'localhost' IDENTIFIED BY 'Museum@123456';
GRANT ALL ON museum_reservation.* TO 'museum'@'localhost';
FLUSH PRIVILEGES;
"
echo "数据库和用户创建成功"
```

### 2.2 导入表结构和初始数据

```bash
sudo mysql museum_reservation < ~/web-homework/museum-reservation-system/database/schema.sql
echo "表结构导入成功"
```

### 2.3 验证

```bash
mysql -u museum -p'Museum@123456' museum_reservation -e "
SHOW TABLES;
SELECT COUNT(*) AS slot_count FROM reservation_slot;
SELECT COUNT(*) AS activity_count FROM reservation_activity;
"
```

预期输出：8 张表，12 个时段，3 个活动。

## 三、构建并启动后端

### 3.1 构建 JAR 包

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
```


预期输出包含 `"status": "UP"` 和 `"database": "UP"`。

## 四、确保活动和时段有效

```bash
export MYSQL_PWD='Museum@123456'

SELECT id, activity_name, status, booking_start, booking_end
```

## 五、测试1：418并发预约（数据一致性）

### 目的

测试 418 人同时抢 50 个名额时，系统是否能保证：成功数 = 名额 = 50，无超额、无重复。

### 操作步骤

```bash
cd ~/web-homework/museum-reservation-system/scripts/perf
chmod +x concurrency_test.sh
export DB_PASSWORD='Museum@123456'

./concurrency_test.sh 1 50 418 100 http://127.0.0.1:8080
# 参数说明：时段ID=1  名额=50  总请求数=418  并发数=100  后端地址
```

### 预期输出

```
==== 并发预约压测 ====
时段ID=1  名额=50  请求数=418  并发=100  目标=http://127.0.0.1:8080
开始并发请求 ...

==== 结果 ====
总耗时(s):        2.82
吞吐(req/s):      148.3
HTTP 200 成功数:  50
被拒绝(名额满等): 368
DB booked_count:  50
DB 预约记录数:    50
DB 不同身份证数:  50  (用于验证无重复)

[PASS] 成功数 = booked_count = 记录数 = 名额(50)，未超额。
[PASS] 记录数 = 不同身份证数，无重复预约。
```

### 结果记录

| 指标 | 实测值 |
|------|--------|
| 总耗时(s) | 2.82 |
| 吞吐量(req/s) | 148.3 |
| HTTP 200 成功数 | 50 |
| 被拒绝数 | 368 |

## 六、测试2：读接口高并发（ab 压测）

### 目的

测试 3 个只读接口在 5000 请求 / 100 并发下的吞吐量和响应时间。

### 操作步骤

依次执行以下 3 个命令（每个跑完再跑下一个）：

```bash
# 1. 查询可预约时段
ab -n 5000 -c 100 http://127.0.0.1:8080/api/slots

# 2. 查询场馆信息
ab -n 5000 -c 100 http://127.0.0.1:8080/api/museum/info

# 3. 查询公告
ab -n 5000 -c 100 http://127.0.0.1:8080/api/notices
```

### 如何读 ab 输出

ab 输出中关注以下字段：

| ab 输出行 | 对应指标 |
|---|---|
| `Requests per second` | 吞吐量 (req/s) |
| `Time per request`（第一行） | 平均响应时间 (ms) |
| `Failed requests` | 失败请求数 |
| `50%  xxx` | P50 延迟 |
| `90%  xxx` | P90 延迟 |
| `95%  xxx` | P95 延迟 |
| `99%  xxx` | P99 延迟 |
| `100% xxx` | 最慢请求 |

### 结果记录

| 接口 | 吞吐量(req/s) | 平均响应(ms) | P50(ms) | P90(ms) | P95(ms) | P99(ms) | 最慢(ms) | 失败数 |
|------|------------|------------|---------|---------|---------|---------|----------|--------|
| GET /api/slots | 1016.86 | 98.34 | 88 | 154 | 178 | 221 | 359 | 0 |
| GET /api/museum/info | 2205.69 | 45.34 | 42 | 65 | 74 | 95 | 150 | 0 |
| GET /api/notices | 3067.21 | 32.60 | 29 | 56 | 69 | 95 | 192 | 0 |

## 七、测试3：大数据量查询性能

### 目的

往数据库灌入大量数据（0 → 1千 → 1万 → 5万 → 10万条），观察查询接口是否变慢。

### 7.1 创建存储过程

```bash
export MYSQL_PWD='Museum@123456'
mysql -u museum museum_reservation <<'EOF'
DELIMITER //
CREATE PROCEDURE IF NOT EXISTS insert_test_data(IN total INT)
BEGIN
    DECLARE i INT DEFAULT 1;
    UPDATE reservation_slot SET total_capacity = total + 1000 WHERE id = 1;
    WHILE i <= total DO
        INSERT IGNORE INTO visitor (name, id_card, phone)
        VALUES (CONCAT('测试游客', i), CONCAT('3201', LPAD(i, 14, '0')), CONCAT('138', LPAD(i, 8, '0')));
        INSERT IGNORE INTO reservation_record
            (reservation_no, visitor_id, activity_id, slot_id, id_card, phone, visit_date, slot_name, status, qr_content)
        SELECT CONCAT('MR-TEST-', LPAD(i, 8, '0')), v.id, 1, 1, v.id_card, v.phone,
            CURDATE() - INTERVAL 1 DAY, '测试场次', 'SUCCESS', CONCAT('QR-TEST-', i)
        FROM visitor v WHERE v.id_card = CONCAT('3201', LPAD(i, 14, '0'));
        SET i = i + 1;
    END WHILE;
END //
DELIMITER ;
EOF
echo "存储过程创建成功"
```

### 7.2 逐档测试

每个档位的测试命令（4 个接口）：

```bash
ab -n 1000 -c 50 http://127.0.0.1:8080/api/slots
ab -n 1000 -c 50 http://127.0.0.1:8080/api/museum/info
ab -n 1000 -c 50 http://127.0.0.1:8080/api/notices
ab -n 1000 -c 50 "http://127.0.0.1:8080/api/reservations/my?idCard=320100000000000001"
```

操作流程：

```
第0档：直接跑上面 4 个 ab 命令，记录 0 条时的数据

第1档：灌入 1000 条 → mysql -u museum -p'Museum@123456' museum_reservation -e "CALL insert_test_data(1000);"
       跑 4 个 ab 命令，记录数据

第2档：灌入 10000 条 → mysql -u museum -p'Museum@123456' museum_reservation -e "CALL insert_test_data(10000);"
       跑 4 个 ab 命令，记录数据

第3档：灌入 50000 条 → mysql -u museum -p'Museum@123456' museum_reservation -e "CALL insert_test_data(50000);"
       跑 4 个 ab 命令，记录数据

第4档：灌入 100000 条 → mysql -u museum -p'Museum@123456' museum_reservation -e "CALL insert_test_data(100000);"
       跑 4 个 ab 命令，记录数据
```

> 注意：每个档位是**累积**的，不用清数据。存储过程用 `INSERT IGNORE` 避免重复。

### 结果记录

| 接口 | 0条 | 1千条 | 1万条 | 5万条 | 10万条 |
|------|-----|------|------|------|-------|
| GET /api/slots avg(ms) | 24.32 | 20.46 | 18.69 | 18.54 | 19.49 |
| GET /api/museum/info avg(ms) | 15.07 | 13.60 | 13.42 | 13.91 | 15.59 |
| GET /api/notices avg(ms) | 15.82 | 17.30 | 13.36 | 10.80 | 25.65 |
| GET /api/reservations/my avg(ms) | 17.63 | 16.45 | 14.80 | 16.30 | 23.79 |

**结论**：读接口响应基本稳定，10万条记录时部分接口略有上升但仍在可接受范围内。

### 7.3 清理测试数据

```bash
export MYSQL_PWD='Museum@123456'
mysql -u museum museum_reservation -e "
DELETE FROM reservation_record WHERE reservation_no LIKE 'MR-TEST-%';
DELETE FROM visitor WHERE id_card LIKE '3201%';
UPDATE reservation_slot SET booked_count=0, version=0 WHERE id=1;
"
echo "测试数据清理完成"
```

## 八、测试4：并发极限阶梯测试

### 目的

逐步加大并发量（100 → 500 → 1000 → 2000 → 5000），找到系统的并发极限。名额设为 10000，避免"名额满"干扰结果。

### 操作步骤

**每轮测试前必须执行重置 SQL**：

```bash
export MYSQL_PWD='Museum@123456'
mysql -u museum museum_reservation -e "
UPDATE reservation_slot SET total_capacity=10000, booked_count=0, version=0 WHERE id=1;
DELETE FROM reservation_record WHERE slot_id=1;
DELETE FROM request_log;
"
```

然后执行测试：

```bash
cd ~/web-homework/museum-reservation-system/scripts/perf
export DB_PASSWORD='Museum@123456'

# 第1轮：100并发
./concurrency_test.sh 1 10000 100 100 http://127.0.0.1:8080
# ↑ 跑完后执行上面的重置 SQL，再跑下一轮

# 第2轮：500并发
./concurrency_test.sh 1 10000 500 500 http://127.0.0.1:8080

# 第3轮：1000并发
./concurrency_test.sh 1 10000 1000 1000 http://127.0.0.1:8080

# 第4轮：2000并发
./concurrency_test.sh 1 10000 2000 2000 http://127.0.0.1:8080

# 第5轮：5000并发
./concurrency_test.sh 1 10000 5000 5000 http://127.0.0.1:8080
```

> **重要**：每轮之间必须执行重置 SQL！否则前一轮的预约记录会影响下一轮结果。

### 结果记录

| 轮次 | 并发数 | 总耗时(s) | 吞吐(req/s) | 成功数 | 被拒绝 | 结论 |
|------|--------|----------|------------|--------|--------|------|
| 第1轮 | 100 | 0.51 | 196.8 | 100 | 0 | 全部成功，数据一致 |
| 第2轮 | 500 | 2.29 | 218.3 | 500 | 0 | 全部成功，数据一致 |
| 第3轮 | 1,000 | 3.98 | 251.2 | 1000 | 0 | 全部成功，数据一致 |
| 第4轮 | 2,000 | 7.20 | 277.9 | 2000 | 0 | 全部成功，数据一致 |
| 第5轮 | 5,000 | 18.16 | 275.4 | 5000 | 0 | 全部成功，数据一致 |

**结论**：
- 系统在 5000 并发下仍然全部成功，无超额、无重复，数据完全一致。
- 吞吐量在 2000 并发时达到峰值 277.9 req/s，5000 并发时吞吐略降至 275.4 req/s，说明系统开始饱和。
- 整个测试过程中 **booked_count = 记录数 = 不同身份证数**，数据安全性完全保证。

## 十、常见问题

### Q1: `ERROR 1045 Access denied for user 'museum'@'localhost'`

数据库密码不对。确认你用的是 `Museum@123456`（部署脚本 `01-init-database.sh` 创建 museum 用户时的默认密码）。

### Q2: 活动状态不是 OPEN 或预约时间窗口已过期

```bash
export MYSQL_PWD='Museum@123456'
mysql -u museum museum_reservation -e "
UPDATE reservation_activity SET status='OPEN',
  booking_start=NOW()-INTERVAL 1 HOUR,
  booking_end=NOW()+INTERVAL 24 HOUR
WHERE id=1;
"
```

### Q3: `concurrency_test.sh` 报 [FAIL] 但数据实际是一致的

如果你在测试4中使用 `capacity=10000` 但发送的请求数少于 10000，脚本会报 FAIL（因为成功数 ≠ 名额），但只要 **成功数 = booked_count = 记录数 = 不同身份证数**，数据一致性就是通过的。

### Q4: curl 报 `Connection refused`

后端没有启动。回到第三步启动后端服务。

### Q5: Java 版本不对

```bash
sudo update-alternatives --config java
# 选择 java-21-openjdk-amd64
```
