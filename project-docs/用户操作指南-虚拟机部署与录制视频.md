# E. 虚拟机真机部署(VMware,固定 8GB)

部署后架构:宿主机浏览器 → Nginx:80(前端 + 反代 `/api`)→ Spring Boot:8080 → MySQL 8。
一键脚本位于 `museum-reservation-system/deploy/`,以下按顺序操作即可。

## E-1. 新建虚拟机

1. 打开 VMware Workstation / Player → 新建虚拟机。
2. 安装 **Ubuntu 22.04 桌面版或服务器版**(推荐;CentOS 7/8 也可)。
3. **内存固定分配 8192 MB(8GB)** —— 作业硬性要求,务必设成 8192。
4. 处理器 ≥ 2 核,磁盘 ≥ 20GB。
5. 网络模式选 **NAT** 或 **桥接**(保证宿主机能访问虚拟机 IP)。
6. 启动并完成系统安装,确保虚拟机能联网(脚本要在线装 JDK/Node/MySQL/Nginx)。

## E-2. 查看虚拟机 IP(后面宿主机访问要用)

```bash
ip addr | grep inet
```
记下类似 `192.168.x.x` 的地址(NAT 通常是 192.168.x.x,桥接是你局域网网段)。

## E-3. 把项目拷进虚拟机

任选一种:
- **方式 A(推荐,联网克隆)**:
  ```bash
  sudo apt-get update && sudo apt-get install -y git
  git clone https://github.com/123s1/web-homework.git
  cd web-homework/museum-reservation-system/deploy
  ```
- **方式 B(共享/U盘/拖拽)**:把整个 `museum-reservation-system` 目录拷到虚拟机,例如 `~/museum-reservation-system`,然后:
  ```bash
  cd ~/museum-reservation-system/deploy
  ```

> 注意:确保拷进去的是**含 `deploy/` 目录**的最新版本(已合并测试分支后的 main)。

## E-4. 准备部署配置

```bash
cp deploy.env.example deploy.env
nano deploy.env        # 按需修改:数据库密码、端口等(默认即可跑通)
```
重点字段(打开看一眼即可,默认值能直接用):
- `DB_PASSWORD`:MySQL 中本系统库的密码(可保持默认或自定义)。
- 端口默认:Nginx 80、后端 8080、MySQL 3306。

## E-5. 一键部署

```bash
sudo ./deploy-all.sh
```
该脚本会依次:安装 JDK21/Node/MySQL/Nginx → 建库导入 `schema.sql` → 构建前端 dist 与后端 jar → 配置 systemd 服务 `museum-backend` 与 Nginx → 启动。

> 若想分步执行,也可依次运行:`00-install-prereqs.sh` → `01-init-database.sh` → `02-build.sh` → `03-deploy.sh`(见 `deploy/README.md`)。

## E-6. 放行 80 端口(如开了防火墙)

- Ubuntu(ufw):
  ```bash
  sudo ufw allow 80/tcp && sudo ufw allow 8080/tcp
  ```
- CentOS(firewalld):
  ```bash
  sudo firewall-cmd --permanent --add-port=80/tcp --add-port=8080/tcp && sudo firewall-cmd --reload
  ```

## E-7. 验证(并截图留证 —— 这是部署 10 分的证据)

在**虚拟机内**:
```bash
free -h                              # 截图:确认内存为 8G(Mem 行 total ≈ 7.7Gi~8.0Gi)
java -version                        # 截图:JDK 版本
systemctl status museum-backend      # 截图:服务 active (running)
curl http://127.0.0.1/api/health     # 截图:返回健康状态(UP/success)
```
在**宿主机浏览器**:
- 打开 `http://<虚拟机IP>/`(用 E-2 记下的 IP)→ 截图首页正常显示。
- 走一遍游客预约 + 管理员登录,确认功能可用 → 截图。

> 把以上截图保存好,既用于答辩,也可放进最终压缩包的「测试截图」或部署说明里。

## E-8. 常见问题排查

| 现象 | 排查 |
|---|---|
| 宿主机打不开页面 | 确认虚拟机 IP、80 端口已放行;`systemctl status nginx` 是否 active |
| 接口 502 | `systemctl status museum-backend`、`journalctl -u museum-backend -n 100` 看后端日志 |
| 建库失败 | 确认 MySQL 已启动 `systemctl status mysql`;`deploy.env` 密码与实际一致 |
| 内存不是 8G | 关机 → VMware 虚拟机设置 → 内存改为 8192MB |

> 部署中如有报错,把对应命令的输出/日志发给我(Devin),我帮你定位。

# F. 录制系统演示视频(≤5 分钟)

## F-1. 录制前准备

- 系统已按 E 部署好并可正常访问(宿主机能打开页面)。
- 准备录屏软件(OBS Studio / Windows 自带 Xbox Game Bar `Win+G` / 录屏工具均可),**开启麦克风**。
- 打开需要的窗口:VMware 虚拟机、宿主机浏览器、JMeter(并发演示用)。
- 解说词见 `project-docs/演示视频解说脚本.md`,照着念即可。

## F-2. 录制分镜(总时长控制在 5 分钟内)

| 段落 | 时长 | 画面内容 |
|---|---|---|
| 1 部署环境 | ~30s | 展示 VMware 虚拟机内存 8G(`free -h`)、`curl /api/health` 返回 UP |
| 2 后台配置 | ~60s | 管理员登录 → 配置/查看预约活动、分时时段、名额 |
| 3 前端预约 | ~90s | 游客实名登录 → 选时段 → 预约成功 + 二维码;再演示重复预约/名额已满/时间拦截的提示 |
| 4 并发测试 | ~60s | 运行 JMeter(或 `scripts/perf/concurrency_test.sh`),展示高并发下成功数=名额数、无超额 |
| 5 数据核对 | ~30s | 后台预约记录/剩余名额与配置一致;`booked_count` 未超过 `total_capacity` |

## F-3. 录制要求

- 画面清晰、声音正常、**时长不超过 5 分钟**。
- 覆盖上述 5 段(尤其第 3、4 段是功能与一致性的核心得分点)。
- 录好后命名如 `演示视频.mp4`。

## F-4. 放入最终压缩包

把录好的视频放到打包目录(Devin 打包时会预留 `演示视频请放这里` 目录),或单独提供网盘链接说明。
