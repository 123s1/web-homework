# 省博物馆参观预约系统前端开发设计

## 1. 文档目的

本文档用于指导省博物馆参观预约系统前端开发，明确前端技术栈、页面结构、路由设计、接口调用方式、页面与后端接口对应关系、前端校验规则、联调测试方案和开发顺序。

本文档依据：

- `项目设计开发流程.md`
- `项目要求分析.md`
- `project-docs/需求拆分.md`
- `project-docs/系统设计文档初稿.md`
- `project-docs/数据库设计.md`
- `project-docs/后端接口设计.md`
- 已完成的 Spring Boot 后端接口代码

当前后端接口已经按照 `后端接口设计.md` 全部实现并测试通过，因此前端可以直接基于后端 REST API 进行页面开发和联调。

---

## 2. 前端开发目标

前端需要完成一个可运行、可演示、可联调的省博物馆分时预约系统，主要目标包括：

- 游客可以查看场馆信息和公告通知。
- 游客可以实名登录。
- 游客可以查询可预约日期和时段。
- 游客可以提交预约并查看预约成功凭证。
- 游客可以根据身份证号查询自己的预约记录。
- 管理员可以登录后台。
- 管理员可以维护场馆信息。
- 管理员可以维护公告通知。
- 管理员可以维护预约活动。
- 管理员可以维护预约时段和名额。
- 管理员可以查询预约名单。
- 管理员可以导出预约名单 CSV。
- 管理员可以查看后台统计和系统状态。

前端不直接访问数据库，所有数据均通过 Axios 调用后端接口获得。

---

## 3. 前端技术栈

根据 `项目设计开发流程.md` 中的项目定位，前端技术栈采用：

```text
Vue 3 + Axios + Bootstrap
```

建议具体版本与工具：

```text
构建工具：Vite
前端框架：Vue 3
路由管理：Vue Router
HTTP 请求：Axios
UI 样式：Bootstrap 5
图表增强：可选 Chart.js
二维码展示：可选 qrcode.vue 或普通文本凭证
```

说明：

- Bootstrap 适合课程大作业，开发速度快，部署简单。
- Vue Router 用于游客端和管理员端页面切换。
- Axios 统一封装后端接口调用。
- 后端暂未引入正式 Token 鉴权，因此前端登录状态第一版可使用 `localStorage` 保存基础登录信息。

| 路由 | 页面组件 | 功能 |

| 路由 | 页面组件 | 功能 |
| --- | --- | --- |
| `/admin/login` | `AdminLoginView.vue` | 管理员登录 |

### 5.3 路由守卫设计

第一版不引入复杂权限系统，采用简单登录状态判断：

```text

管理员端：访问 /admin 相关页面时，检查 localStorage 中是否存在 adminInfo。
```

如果未登录：

```text
游客跳转 /visitor/login
管理员跳转 /admin/login
```

## 6. Axios 请求封装设计

### 6.1 基础请求封装

文件：

```text
src/api/request.js
```

职责：

- 设置 `baseURL`。
- 设置请求超时时间。
- 统一处理后端 `ApiResponse` 格式。
- 统一处理错误提示。

开发环境建议：

```text
baseURL = http://127.0.0.1:8080
```

也可以在 `.env.development` 中配置：

```text
VITE_API_BASE_URL=http://127.0.0.1:8080
```

后端统一响应格式：

```json
{
  "success": true,
  "message": "操作成功",
  "data": {}
}
```

前端处理规则：

```text
success = true：返回 data。
success = false：弹出 message，并抛出错误。
HTTP 500 或网络错误：提示系统繁忙或网络异常。
```

### 6.2 API 文件拆分

| 文件 | 职责 |
| --- | --- |
| `museum.js` | 场馆信息、公告、可预约时段 |
| `visitor.js` | 游客实名登录 |
| `reservation.js` | 提交预约、我的预约 |
| `admin.js` | 管理员登录和后台管理接口 |

## 7. 游客端页面设计

### 7.1 场馆首页 HomeView

功能：

- 展示场馆名称、地址、开放信息、参观须知。
- 展示启用公告列表。
- 提供“立即预约”按钮。
- 提供“我的预约”入口。

调用接口：

```text
GET /api/museum/info
GET /api/notices
```

页面状态：

```text
加载中
加载成功
加载失败
公告为空
```

---

### 7.2 游客实名登录 VisitorLoginView

功能：

- 输入姓名。
- 输入身份证号。
- 输入手机号。
- 调用后端实名登录接口。
- 登录成功后保存游客信息到 `localStorage`。

调用接口：

```text
POST /api/visitor/login
```

表单校验：

```text
姓名不能为空
身份证号必须为 18 位，最后一位可为数字或 X/x
手机号必须为 11 位大陆手机号格式
```

保存数据：

```text
visitorInfo = {
  visitorId,
  name,
  idCard,
  phone
}
```

---

### 7.3 预约时段选择 SlotListView

功能：

- 查询可预约时段。
- 支持按参观日期筛选。
- 展示日期、时段名称、开始时间、结束时间、总名额、已预约人数、剩余名额。
- 剩余名额为 0 时禁用预约按钮。
- 点击预约按钮后调用提交预约接口。

调用接口：

```text
GET /api/slots
GET /api/slots?visitDate=yyyy-MM-dd
POST /api/reservations
```

预约前置条件：

```text
游客必须先实名登录。
slotId 必须存在。
remaining > 0 时才允许点击预约按钮。
```

注意：

```text
前端只能做体验层校验，最终是否可预约以后端返回结果为准。
后端已经实现事务、唯一约束和条件更新防止超额预约。
```

---

### 7.4 预约结果 ReservationResultView

功能：

- 展示预约成功或失败信息。
- 成功时展示预约编号、参观日期、时段、二维码内容。
- 提供返回首页、查看我的预约按钮。

数据来源：

```text
POST /api/reservations 返回结果
```

二维码展示：

第一版可以直接展示 `qrContent` 文本。

增强版可以使用二维码组件生成二维码图片。

---

### 7.5 我的预约 MyReservationsView

功能：

- 根据当前游客身份证号查询预约记录。
- 也可以允许手动输入身份证号查询。
- 展示预约编号、日期、时段、状态、二维码内容、创建时间。

调用接口：

```text
GET /api/reservations/my?idCard=身份证号
```

空状态：

```text
暂无预约记录
```

### 8.6 预约时段管理 SlotManageView

调用接口：

```text
GET /api/admin/slots

GET /api/admin/slots?visitDate=yyyy-MM-dd
```

注意：



CSV 导出说明：

功能：

## 11. 前端表单校验设计

前端表单校验用于提升用户体验，但不能替代后端校验。

### 11.1 身份证号校验

规则：

```text
18 位，前 17 位数字，最后一位数字或 X/x
```

正则：

```text
^[0-9]{17}[0-9Xx]$
```

### 11.2 手机号校验

规则：

```text
大陆 11 位手机号，1 开头，第二位 3-9
```

正则：

```text
^1[3-9][0-9]{9}$
```

### 11.3 日期时间校验

预约活动表单需要校验：

```text
bookingEnd > bookingStart
dailyCapacity > 0
personLimit > 0
```

预约时段表单需要校验：

```text
endTime > startTime
totalCapacity > 0
enabled 只能是 0 或 1
```

## 12. 错误处理与提示设计

统一处理后端错误：

```text
success=false 时显示 message。
网络错误时显示：网络异常，请稍后重试。
系统错误时显示：系统繁忙，请稍后重试。
表单错误时在对应输入框下方展示提示。
```

常见业务错误：

| 场景 | 前端提示来源 |
| --- | --- |
| 身份证号格式不正确 | 后端 message 或前端校验 |
| 手机号格式不正确 | 后端 message 或前端校验 |
| 预约时段不存在 | 后端 message |
| 预约活动未开放 | 后端 message |
| 预约尚未开始 | 后端 message |
| 预约已经结束 | 后端 message |
| 同一天重复预约 | 后端 message |
| 预约名额已满 | 后端 message |
| 管理员账号密码错误 | 后端 message |

## 16. 当前还建议补充的内容

当前后端、数据库和接口文档已经比较完整。前端开发前，建议再补充或确认以下内容：

### 16.1 是否需要正式登录 Token

当前后端管理员登录和游客登录是课程大作业阶段的简单登录，不返回 JWT 或 Session Token。

前端第一版可以使用 `localStorage` 保存登录信息。

如果老师要求更严格权限控制，后续可补充：

```text
JWT 登录认证
请求拦截器添加 Authorization Header
后端登录拦截器
```

但这不是当前主线必须项。

### 16.2 是否需要取消预约功能

当前接口文档和后端代码没有设计取消预约接口。

如果业务要求“游客可以取消预约”，需要新增：

```text
PUT /api/reservations/{id}/cancel
```

并在事务中：

```text
更新 reservation_record.status = CANCELLED
减少 reservation_slot.booked_count
```

目前项目主线没有要求，可以暂不做。

### 16.3 是否需要扫码核验功能

当前系统只生成 `qrContent`，不包含扫码核验接口。

如果需要现场核验，可以后续扩展：

```text
GET /api/reservations/verify?reservationNo=xxx
```

课程大作业第一版可以只展示二维码内容或预约凭证。

### 16.4 是否需要请求日志写入

当前 `request_log` 表存在，`GET /api/admin/status` 可以统计它，但后端暂未统一写入请求日志。

如果希望系统状态页展示真实请求量，可以后续补充：

```text
预约接口成功/失败时写入 request_log
或使用拦截器统一记录关键请求
```

当前不影响核心预约功能。

### 16.5 是否需要更强的图表展示

后台统计第一版可以用表格和数字卡片展示。

如果时间充足，可以增加：

```text
Chart.js 柱状图
预约名额占用饼图
按日期预约趋势图
```

## 18. 总结

前端开发应基于已经完成的后端 REST API 实现。当前建议优先完成游客端预约闭环，再完成管理员后台管理闭环。

核心闭环为：

```text
游客首页 -> 游客实名登录 -> 查询可预约时段 -> 提交预约 -> 查看预约凭证 -> 我的预约记录
```

后台闭环为：

```text
管理员登录 -> 后台统计 -> 场馆管理 -> 公告管理 -> 活动管理 -> 时段管理 -> 预约名单查询 -> CSV 导出 -> 系统状态查看
```

完成本文档后，可以进入前端项目搭建与页面开发阶段。
